# Workflow First: Making Better Automation and AI Decisions

This workshop now concentrates on one developer use case:
**get this repository building and all critical tests passing**.

## Original intent

Irene Momper proposed a one-hour workshop focused on business workflow
thinking rather than specific AI tools. The original intent was to help
participants identify work, tasks, decisions, handoffs, outcomes, and the
appropriate balance of automation, AI assistance, and human ownership. The
workshop should begin with the problem and remain useful as technology changes.

The current contract preserves that intent while narrowing the first
implementation to one publication-safe developer workflow. The customer
conversation is not used as a source of confidential facts or a customer
scenario.

## Current contract reconciliation

| Requirement | Current implementation |
| --- | --- |
| Start with the business result | S01 starts with the repository build and critical-test goal. |
| Choose technology after the goal | S04-S05 compare harnesses after the goal and whole route. |
| Explain planning, governance, and boundaries | S06-S14 treat Planning as one stage with eight properties. |
| Make evidence and accountability explicit | S10 defines verification; S15 shows completion evidence; S16-S17 require human review and authorization. |
| Preserve a durable, reusable framework | The route is technology-neutral and can be extended to other use cases after this one is reviewed. |
| Keep the experience publication-safe | No customer facts, live access, execution authority, or unsupported product claims are included. |

Additional personas and goals are deliberately deferred. A later expansion
must update the requirements, exact-copy source, manifest, module contract,
learning architecture, experience plan, and validation evidence together.

## Outcomes

- Define a developer goal with properties, evidence, boundaries, and stop
  conditions.
- Compare harness choices without treating a named tool as authority.
- Build a plan covering stack, governance, artifacts, verification, boundaries,
  execution, and explicit stops.
- Review completion evidence and require human approval before consequential
  action.
